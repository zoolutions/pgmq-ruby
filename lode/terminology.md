# Terminology

- **PGMQ** — the PostgreSQL extension (`pgmq` schema) this gem drives. Not this gem; the gem is `pgmq-ruby`, the constant is `PGMQ`.
- **low-level client** — the project's own framing: a transport layer of direct SQL wrappers, with job processing, retries, instrumentation and Rails integration explicitly out of scope and assigned to a planned `pgmq-framework` gem (`lib/pgmq.rb:13-17`, `README.md:8-19`).
- **queue name** — the argument nearly every method takes; validated by `Client#validate_queue_name!` (non-empty, under 48 characters, `/\A[a-zA-Z_][a-zA-Z0-9_]*\z/`). PGMQ derives table names from it (`pgmq.q_<name>`, `pgmq.a_<name>`), which is why it is stricter than a PostgreSQL identifier.
- **raw value** — every scalar the client returns. No `type_map_for_results` is installed, so `msg_id` is `"123"`, a boolean is `"t"`/`"f"`, a count is `"3"`, and a JSONB payload is its unparsed String (`lib/pgmq/connection.rb:237-239`, `lib/pgmq/message.rb:26-40`).
- **`vt` (visibility timeout)** — seconds a read message stays invisible to other readers. `DEFAULT_VT = 30` (`lib/pgmq/client.rb:39`). In `set_vt` and `set_vt_batch` it is overloaded: exactly `vt.is_a?(Time)` takes the `timestamptz` overload (`message_lifecycle.rb:250`, `:292` — the only two `is_a?(Time)` tests in `lib/`), anything else the `integer` offset overload. `set_vt_multi` has no branch of its own; it calls `set_vt_batch` per queue inside a transaction.
- **produce / consume** — this gem's names for PGMQ's `send` / `read`. `produce` maps to `pgmq.send`, `produce_batch` to `pgmq.send_batch`; `send` is left alone because it is `Object#send`.
- **batch / multi** — two different axes. `*_batch` is many messages in one queue (`delete_batch`, `archive_batch`, `set_vt_batch`). `*_multi` is several queues at once: `read_multi`/`pop_multi` in one `UNION ALL` query, `delete_multi`/`archive_multi`/`set_vt_multi` in one transaction.
- **conditional** — a Hash serialised to JSONB and passed to `pgmq.read`'s filter argument; an empty Hash selects the overload without it (`lib/pgmq/client/consumer.rb:34-44`).
- **grouped round-robin (`read_grouped_rr`)** — PGMQ orders results round-robin across groups keyed by the first key of each JSON payload, so one busy entity cannot monopolise a worker.
- **topic routing** — AMQP-style `bind_topic`/`produce_topic` over `pgmq.send_topic`; patterns use `*` (one word) and `#` (zero or more). Requires PGMQ v1.11.0+, which the test helpers detect (`test/support/database_helpers.rb:55-65`).
- **callable connection** — a Proc passed instead of connection params, so the pool asks the host app for each connection (`-> { ActiveRecord::Base.connection.raw_connection }`). It must return a *distinct* `PG::Connection` per pool slot; see `connection/summary.md`.
- **shared-connection guard** — the `ObjectSpace::WeakKeyMap` check in `create_pool` that raises `ConfigurationError` when a callable returns a connection the pool has already taken (`lib/pgmq/connection.rb:198-221`).
- **transactional client** — `PGMQ::Transaction::TransactionalClient`, the `method_missing` wrapper `#transaction` yields. Its operations land in the transaction because `connection_pool`'s checkout is re-entrant per thread, not because the wrapper redirects them.
- **example / integration spec** — a standalone script under `spec/integration/` run by `bin/integrations` as a subprocess, not a Minitest file. Unit tests live in `test/lib/`.
- **lint bundle** — `Gemfile.lint` plus `Gemfile.lint.lock`, a second bundle holding `standard`, `rubocop-*` and `yard-lint`; CI runs those jobs with `BUNDLE_GEMFILE=Gemfile.lint` (`.github/workflows/ci.yml:119`, `136`).
- **lode** — this directory: the repository's durable memory. `lode/review/` holds accepted review findings as rules; `/lode:gate` enforces them before a push.
