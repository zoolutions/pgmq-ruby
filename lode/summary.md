# pgmq-ruby

A low-level Ruby client for PGMQ, the PostgreSQL message-queue extension. `PGMQ::Client` wraps 28 `pgmq.*` SQL functions (plus one private read of the `pgmq.meta` table in `queue_management.rb#queue_exists?`) close to one-to-one over a `connection_pool`-backed pool of `PG::Connection`s, and stops there: job processing, retry strategies, instrumentation and Rails integration are deliberately left to a planned `pgmq-framework` gem, the way rdkafka-ruby relates to Karafka (`lib/pgmq.rb:13-17`). Three invariants hold across the gem. **Nothing is converted**: `create_connection` deliberately does not set `type_map_for_results` (`lib/pgmq/connection.rb:237-239`), so every value that comes back — message IDs, counts, booleans, timestamps, JSONB payloads — is the String PostgreSQL printed, and callers do their own parsing. **A queue name reaches SQL only after `Client#validate_queue_name!`** (`lib/pgmq/client.rb:109-137`), which matters because `read_multi` and `pop_multi` are the only two methods that build SQL by interpolation rather than binding (`lib/pgmq/client/multi_queue.rb:58-66`, `176-181`). **The pool owns connection identity**: a callable that hands the same `PG::Connection` to two pool slots raises `PGMQ::Errors::ConfigurationError` at slot-creation time rather than letting concurrent threads corrupt libpq state (`lib/pgmq/connection.rb:196-227`).

`zoolutions/pgmq-ruby` is a fork of `mensfeld/pgmq-ruby`. Its `master` carries no commits of its own — `git rev-list a6f5917..e85899d` is empty, so it is an exact ancestor of upstream's `master` — and it sits 110 commits behind, at upstream's `fix(connection): detect SSL-layer EOF` merge (#99), version `0.6.1`; upstream has since released `0.7.2`. Everything in this lode describes the tree as checked out here, not upstream's. Releases happen upstream in any case: `push.yml` publishes only when `github.repository_owner == 'mensfeld'` (`.github/workflows/push.yml:13`).
